  <action>
Create HtEncoderOptions as a readonly record struct:
- HtSetCount (int, 1 or 2): number of HT Sets per code-block
- IncludeSigProp (bool): whether to include SigProp pass in each HT Set
- IncludeMagRef (bool): whether to include MagRef pass in each HT Set
- TargetBpp (float?): target bits per pixel for rate control (null = lossless)
- TargetPsnr (float?): target PSNR in dB (null = no PSNR target)
- Static named presets:
  - Diagnostic: 2 Sets, all passes, TargetPsnr=40+ dB
  - Archive: 2 Sets, all passes, TargetPsnr=35+ dB
  - Review: 1 Set, SigProp+MagRef, TargetPsnr=30+ dB
  - Fast: 1 Set, cleanup-only, TargetPsnr=25+ dB
  - Lossless: 2 Sets, all passes, no rate target (full precision)

Update Htj2kCodecOptions:
- Add HtEncoderOptions? HtOptions property (null = use defaults based on lossless/lossy)
- Default for lossless: HtEncoderOptions.Lossless
- Default for lossy: HtEncoderOptions.Diagnostic

Update PacketEncoder:
- Add parameter or flag to indicate HT mode
- In HT mode: pass count per code-block is 1-6 (not the EBCOT formula of 3 per bitplane)
- WritePassCount must handle the smaller HT pass count range
- Placeholder passes: if a code-block has fewer passes than the maximum for its HT Set count, signal empty passes per JPEG committee guidelines

Update PacketDecoder:
- ReadPassCount must handle HT pass count range (1-6)
- Detect HT mode from CAP marker presence in codestream header

Update J2kCodestream:
- Parse CAP marker (0xFF50) to detect HTJ2K codestreams
- Extract Pcap (Part 15 bit), Ccap[15] (mode, precision, HTREV/HTIRV)
- Add properties: IsHtj2k (bool), HtMode (enum: HTONLY, HTDECLARED, MIXED), HtPrecision (int)
- Add static BuildCapMarker(bool isHtOnly, bool isLossless, int precision) method that generates a dynamic CAP marker based on actual encoding parameters (replacing the hardcoded InjectCapMarker in Htj2kCodec.cs)
  </action>
