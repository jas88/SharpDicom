  <action>
Update J2kEncoder.EncodeFrame:
- Accept tile size parameters (via J2kEncoderOptions, defaults to image size = single tile)
- Partition image into tiles: tileCols = ceil(W / tileW), tileRows = ceil(H / tileH)
- For each tile:
  1. Extract tile pixel data from input
  2. Create TileComponent for each component
  3. Apply forward DWT to each TileComponent
  4. Encode code-blocks per subband via IBlockCoder
  5. Build Tier-2 packets per tile
- Write SOT (Start of Tile) + tile data for each tile
- Support all 5 progression orders in packet ordering:
  - LRCP: Layer, Resolution, Component, Position (default)
  - RLCP: Resolution, Layer, Component, Position
  - RPCL: Resolution, Position, Component, Layer (for streaming)
  - PCRL: Position, Component, Resolution, Layer
  - CPRL: Component, Position, Resolution, Layer
- Emit PLT markers for each tile-part (random access, locked decision)
- Update J2kEncoderOptions: add TileWidth, TileHeight (int?), MaxDegreeOfParallelism (int)

Update J2kDecoder.DecodeFrame:
- Parse SOT markers to identify tile boundaries
- For each tile: extract tile data from codestream
- Parallel tile decode using Parallel.For:
  ```csharp
  Parallel.For(0, tileCount, new ParallelOptions
  {
      MaxDegreeOfParallelism = options.MaxDegreeOfParallelism
  }, tileIndex => { DecodeSingleTile(...); });
  ```
- Each tile decoded independently: Tier-2 packet decode, IBlockCoder.DecodeBlock per code-block, inverse DWT
- Stitch decoded tile pixels into output buffer at correct positions
- Handle edge tiles (smaller than full tile size at image boundaries)

Both encoder and decoder:
- Backward compatible: single-tile (no tile partitioning) remains the default
- TileComponent manages per-tile coefficient buffers with ArrayPool
- Thread-safe: no shared mutable state between tiles
