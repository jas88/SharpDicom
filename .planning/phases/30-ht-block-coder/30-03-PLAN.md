Implement the three primitive components of the HT block coding algorithm: VLC lookup tables, MEL run-length coder, and three-stream bidirectional bit I/O.

Purpose: These are the building blocks of the HT cleanup pass. The VLC tables encode quad significance patterns, the MEL coder handles runs of insignificant quads, and HtBitIO manages the three interleaved byte-streams (VLC, MEL, MagSgn) packed into a single codeword segment. Getting these right and tested in isolation is critical before assembling the full cleanup pass.

Output: Three new files in Tier1/ with comprehensive unit tests.

Create VlcTable as a static class with lazy-initialized lookup tables:
- Two tables (Table0, Table1) with 1024 entries each (3-bit context + 7-bit codeword = 10-bit index)
- Each entry is a ushort encoding: bits [3:0] = 4-bit significance pattern, bits [7:4] = embedded magnitude bits (EMB), bits [10:8] = codeword length (1-7 bits)
- Table values derived from ITU-T T.814 specification (use OpenJPH table0.h/table1.h as BSD-2-Clause reference)
- `DecodeVlcQuad(ReadOnlySpan<byte> vlcStream, ref int bitPos, int context)` returns (sigPattern, embBits, codewordLen)
- `EncodeVlcQuad(Span<byte> vlcStream, ref int bitPos, int context, byte sigPattern, byte embBits)` writes VLC codeword
- Lazy initialization: tables computed on first access, cached in static fields
- Thread-safe initialization via Lazy<ushort[]> or static constructor

Create MelCoder with:
- MelEncoder ref struct: writes MEL bits to a backward-growing stream
  - `EncodeQuadSignificance(bool isSignificant)` writes 0 (extend run) or 1 (break run)
  - 13 states with transition table: MelE = {0,0,0,1,1,1,2,2,2,3,3,4,5}
  - State transitions: up on run extension (min 12), down on run break (min 0)
  - Run length = 2^MelE[state]
- MelDecoder ref struct: reads MEL bits from backward stream
  - `DecodeQuadSignificance()` returns bool (true = significant, false = part of run)
  - Same 13-state machine as encoder
  - Reads bits from the end of the segment moving backward
- Both encoder and decoder maintain: state (0-12), run counter, bit buffer

Mark both types as internal. Use [MethodImpl(MethodImplOptions.AggressiveInlining)] on hot-path methods.

Create HtBitIO with two ref structs:

HtCleanupReader:
- Parses a cleanup codeword segment into three streams using the ILW (Interface Locator Word)
- ILW is the last 2 bytes of the segment: 12-bit value marking the VLC/MEL boundary
- MagSgn stream: reads forward from byte 0
- VLC stream: reads forward from ILW offset
- MEL stream: reads backward from end of segment (before ILW bytes)
- `ReadMagSgnBits(int count)` reads N bits from MagSgn stream
- `ReadVlcBits(int count)` peeks bits from VLC stream (for table lookup)
- `AdvanceVlc(int bits)` advances VLC position after lookup
- Internal MelDecoder instance for MEL queries

HtCleanupWriter:
- Builds a cleanup segment from three streams
- MagSgn writer: appends forward
- VLC writer: appends forward
- MEL writer: appends backward
- `Finalize()` merges three streams into single segment with ILW at end
- Uses stackalloc for small segments (<4KB), ArrayPool for larger

Create VlcTableTests:
- Test all 8 possible 3-bit contexts (0-7) produce valid table entries
- Test codeword lengths are in range 1-7
- Test significance patterns are in range 0-15 (4 bits)
- Test encode/decode roundtrip: encode a known significance pattern, decode it, verify match

Create MelCoderTests:
- Test 13-state transitions: run extensions increase state, breaks decrease state
- Test run length matches 2^MelE[state]
- Roundtrip: encode sequence of significant/insignificant quads, decode, verify match
- Test all-insignificant (long run): verify state reaches 12
- Test all-significant (no runs): verify state stays at 0

Create HtBitIOTests:
- Test ILW parsing: construct segment with known ILW, verify stream boundaries
- Test MagSgn forward read
- Test VLC forward read
- Test MEL backward read
- Roundtrip: write three streams with HtCleanupWriter, read back with HtCleanupReader, verify all bits match
