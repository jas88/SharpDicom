  <action>
Create ConvertCommand following existing CLI patterns (see StoreCommand.cs, DumpCommand.cs for Command.Create() factory pattern):

`sharpdcm convert [input] --transfer-syntax <ts> [options]`

**Arguments:**
- `input` (required): File path or directory path to convert

**Options:**
- `--transfer-syntax` / `-t` (required): Target transfer syntax. Accept both UIDs and short names:
  - `htj2k-lossless` / `1.2.840.10008.1.2.4.201`
  - `htj2k-lossless-rpcl` / `1.2.840.10008.1.2.4.202`
  - `htj2k-lossy` / `1.2.840.10008.1.2.4.203`
  - `j2k-lossless` / `1.2.840.10008.1.2.4.90`
  - `j2k-lossy` / `1.2.840.10008.1.2.4.91`
  - `jpeg-baseline` / `1.2.840.10008.1.2.4.50`
  - `jpeg-lossless` / `1.2.840.10008.1.2.4.70`
  - `jpeg-ls-lossless` / `1.2.840.10008.1.2.4.80`
  - `rle` / `1.2.840.10008.1.2.5`
  - `explicit-le` / `1.2.840.10008.1.2.1` (decompress)
- `--preset` / `-p`: Quality preset for lossy codecs (diagnostic, archive, review, fast). Default: diagnostic
- `--output` / `-o`: Output directory (default: in-place with .converted.dcm suffix)
- `--force`: Overwrite input files in-place (no suffix)
- `--recursive` / `-r`: Process directories recursively
- `--parallel` / `-j`: Max degree of parallelism (default: CPU count)
- `--dry-run`: Show what would be converted without actually converting
- `--skip-errors`: Continue processing on individual file errors

**Behavior:**
1. Resolve target TransferSyntax from short name or UID
2. Look up source and target codecs via CodecRegistry
3. For each input file:
   a. Read DICOM file
   b. If already in target transfer syntax: skip (log)
   c. If pixel data present: decode with source codec, encode with target codec
   d. Update TransferSyntaxUID in File Meta Information
   e. Write output file
4. TTY-aware progress via ProgressReporter (Spectre.Console when TTY, plain text when piped)
5. Summary at end: N converted, M skipped, K errors

Register in Program.cs:
- Add `rootCommand.Subcommands.Add(ConvertCommand.Create())` alongside existing dump, store, find, lint, fix
