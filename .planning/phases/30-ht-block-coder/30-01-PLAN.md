<objective>
Build the multi-resolution subband infrastructure that maps DWT-decomposed coefficients to their correct subbands (LL/LH/HL/HH at each resolution level) and organizes code-blocks per subband.

Purpose: The existing J2K pipeline has a critical bug: all code-blocks are treated as LL subband (hardcoded subbandType=0 in J2kEncoder.cs line 332). This produces incorrect EBCOT context tables and will produce incorrect HT VLC context formation. Proper subband infrastructure is required before either EBCOT fixes or HT block coder can work correctly.

Output: Three new types in Jpeg2000/Subband/ plus unit tests proving correct subband dimensions and code-block mapping for standard and odd-sized images.
</objective>

  <action>
Create SubbandDescriptor as a readonly struct with:
- SubbandType enum: LL=0, LH=1, HL=2, HH=3 (matches EBCOT context convention)
- ResolutionLevel (int, 0 = lowest/LL)
- Width, Height (subband dimensions at this level)
- OriginX, OriginY (position in coefficient array for this subband)
- CodeBlockGridWidth, CodeBlockGridHeight (number of code-blocks in this subband)

Create SubbandPartitioner as a static class with:
- `GetSubbands(int imageWidth, int imageHeight, int levels, int cbWidth, int cbHeight)` returns SubbandDescriptor[] for all subbands across all resolution levels
- Uses the standard dimension formulas: LL = ceil(W/2) x ceil(H/2), HH = floor(W/2) x floor(H/2), LH = ceil(W/2) x floor(H/2), HL = floor(W/2) x ceil(H/2)
- At each decomposition level, recursively splits the LL subband
- Final result: one LL at lowest level + 3 detail subbands (LH, HL, HH) per level
- `GetSubbandForCodeBlock(SubbandDescriptor[] subbands, int codeBlockX, int codeBlockY, int level)` returns the SubbandType for the given code-block position

Use the existing DwtTransform.GetSubbandDimensions if available, otherwise implement the standard formulas from ITU-T T.800. Ensure correct handling of edge cases: 1x1 images, odd dimensions (e.g., 255x255), very small subbands that have 0 code-blocks.
