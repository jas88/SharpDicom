<objective>
Implement the HT Cleanup pass -- the primary coding pass in the HT block coder that encodes quad significance, sign bits, and magnitude exponents using the three interleaved streams.

Purpose: The Cleanup pass is the core of the HT algorithm and the only mandatory pass per HT Set. It processes coefficients in 2x2 quads, encoding significance patterns via VLC, insignificant-quad runs via MEL, and magnitude/sign bits via MagSgn. This pass alone provides the "cleanup-only" fast encoding mode.

Output: HtCleanup static class with Encode and Decode methods, plus comprehensive roundtrip tests.
</objective>

  <action>
Create HtCleanup as a static class implementing the ITU-T T.814 Cleanup pass:

**Encode method** `Encode(ReadOnlySpan<int> coefficients, int width, int height, int subbandType)` returns `ReadOnlyMemory<byte>` (the cleanup codeword segment):

1. Process coefficients in 2x2 quad groups (row-by-row, left-to-right). Pad to even width/height if needed.
2. For each quad:
   a. Determine significance pattern (4 bits: which of the 4 samples are non-zero)
   b. Determine 3-bit context from neighboring quads (left, above, above-left)
   c. If all-zero quad: MEL encode as insignificant (run extension)
   d. If any non-zero: MEL encode as significant (run break), VLC encode significance pattern + EMB bits
   e. For each significant sample: MagSgn encode sign bit + magnitude bits
3. Finalize: merge VLC + MEL + MagSgn streams into single segment using HtCleanupWriter

**Decode method** `Decode(ReadOnlySpan<byte> segment, Span<int> output, int width, int height, int subbandType)`:

1. Parse segment using HtCleanupReader (finds ILW, splits three streams)
2. Process quads in same order as encoder
3. For each quad:
   a. MEL decode: is this quad significant?
   b. If insignificant: output four zeros
   c. If significant: VLC decode significance pattern + EMB bits, MagSgn decode sign + magnitude
4. Reconstruct coefficient values with correct signs

**Key implementation details:**
- Use 4x4 quad-aligned layout for cache efficiency (locked decision)
- Context formation: 3-bit context from neighbor significance (left=bit0, above=bit1, above-left=bit2)
- Magnitude exponent from number of leading zeros in coefficient absolute value
- EMB bits encode the most significant bit position for significant samples
- Use stackalloc for quad significance state array (< 4KB for typical code-blocks)
- [MethodImpl(MethodImplOptions.AggressiveInlining)] on inner loop methods
- Branchless where possible: use conditional moves for sign extraction
