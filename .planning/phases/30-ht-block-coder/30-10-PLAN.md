Create Htj2kConformanceTests:

**Cross-decoder tests (marked [Explicit] + [Category("Conformance")] since they require OpenJPH binary):**
1. SharpDicom encode -> OpenJPH decode: encode 256x256 8-bit lossless HTJ2K with SharpDicom, invoke `ojph_compress`/`ojph_expand` CLI to decode, compare pixel values
2. OpenJPH encode -> SharpDicom decode: use `ojph_compress` to encode test image, decode with SharpDicom, compare pixel values
3. MIXED mode: encode with SharpDicom MIXED mode (if supported), verify OpenJPH can decode
4. Multi-resolution: encode 512x512 with 5 decomposition levels, decode at each level with both implementations
5. 12-bit lossless: cross-decoder roundtrip for 12-bit medical image data
6. 16-bit lossless: cross-decoder roundtrip for 16-bit

**PSNR verification tests (always run):**
7. Diagnostic preset PSNR: encode with Diagnostic, decode, compute PSNR, assert >= 40 dB
8. Archive preset PSNR: encode with Archive, decode, compute PSNR, assert >= 35 dB
9. Review preset PSNR: encode with Review, decode, compute PSNR, assert >= 30 dB
10. Fast preset PSNR: encode with Fast, decode, compute PSNR, assert >= 25 dB

**SSIM comparison tests:**
11. Diagnostic SSIM: encode/decode, compute SSIM, assert >= 0.98
12. Fast SSIM: encode/decode, compute SSIM, assert >= 0.85

**Lossless exactness tests:**
13. 8-bit lossless: encode/decode, verify byte-exact pixel values
14. 12-bit lossless: encode/decode, verify exact
15. 16-bit lossless: encode/decode, verify exact

PSNR calculation: 10 * log10(maxVal^2 / MSE) where maxVal = (1 << bitsStored) - 1
SSIM calculation: standard formula with default parameters (k1=0.01, k2=0.03)

Create Htj2kPropertyTests using FsCheck:

1. **Lossless roundtrip invariant:** For arbitrary image dimensions (4-512) and bit depth (8/12/16), HT lossless encode followed by decode produces identical pixel values
2. **Codec symmetry:** Encoding the same data twice produces identical codestreams
3. **Cleanup-only subset:** Cleanup-only encode produces valid codestream decodable to some result (may not be pixel-perfect)
4. **Pass count bounds:** Encoded code-blocks have 1-6 passes (never 0, never more than 6)
5. **CAP marker present:** All HT-encoded codestreams contain a valid CAP marker
6. **Output size monotonicity:** Higher quality presets produce larger or equal output than lower presets for same image

Use [Property(MaxTest = 50)] to control test count (balancing coverage vs runtime).
