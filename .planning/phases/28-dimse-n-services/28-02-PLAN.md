private void WriteAsyncOperationsWindow(ushort invoked, ushort performed)
{
    WriteVariableItemHeader(ItemType.AsynchronousOperationsWindow, 4);
    var span = _writer.GetSpan(4);
    BinaryPrimitives.WriteUInt16BigEndian(span, invoked);
    BinaryPrimitives.WriteUInt16BigEndian(span.Slice(2), performed);
    _writer.Advance(4);
}

**FoDicom5.Compat DicomClient.cs:**

The existing `NegotiateAsyncOps` method currently returns `Task.CompletedTask` for default values and throws `NotSupportedException` for non-zero values. Change it to store the invoked/performed values on the underlying SharpDicom DicomClientOptions:

```csharp
public Task NegotiateAsyncOps(int invoked = 0, int performed = 0)
{
    // fo-dicom convention: 0 means "use defaults" (synchronous)
    // SharpDicom convention: 0 means unlimited, 1 means synchronous
    // Map fo-dicom's 0 to SharpDicom's 1 (default/synchronous)
    _options.AsyncOperationsInvoked = invoked == 0 ? (ushort)1 : (ushort)invoked;
    _options.AsyncOperationsPerformed = performed == 0 ? (ushort)1 : (ushort)performed;
    return Task.CompletedTask;
}
```

This removes the NotSupportedException and actually wires the negotiation values through to the underlying client. Note the semantic mapping: fo-dicom uses 0 to mean "default/synchronous" while the DICOM spec uses 0 to mean "unlimited". SharpDicom follows the spec (0=unlimited, 1=synchronous default).
