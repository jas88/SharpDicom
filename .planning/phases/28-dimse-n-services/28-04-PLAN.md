- `DicomUID SOPInstanceUID { get; }` -- the MPPS SOP Instance UID

- Static factory `CreateInProgress(DicomUID sopInstanceUid, DicomDataset attributes)` -- creates an InProgress instance, sets status string "IN PROGRESS"
- Method `DicomDataset CreateCompletedModification()` -- returns a dataset with status "COMPLETED"
- Method `DicomDataset CreateDiscontinuedModification()` -- returns a dataset with status "DISCONTINUED"
- Parse status from string: "IN PROGRESS" -> InProgress, "COMPLETED" -> Completed, "DISCONTINUED" -> Discontinued

Use DicomTag for PerformedProcedureStepStatus (0040,0252). If this tag doesn't exist in WellKnown, define it locally as a static DicomTag in the class.

**InMemoryMppsPersistence.cs:**
Thread-safe in-memory implementation using ConcurrentDictionary<string, MppsInstance>. GetAsync returns null if not found. PutAsync adds or throws if exists. UpdateAsync applies modification list and updates status.

**MppsScpHandler.cs:**
Implements `INCreateHandler` and `INSetHandler`. Constructor takes `IMppsPersistence` (default to `InMemoryMppsPersistence` if null).

`OnNCreateAsync`:
1. Verify SOP Class UID is MPPS (1.2.840.10008.3.1.2.3.3), return NoSuchSOPClass if not
2. Parse the attribute list to create MppsInstance via `MppsInstance.CreateInProgress()`
3. Store via persistence.PutAsync()
4. Return Success with the SOP Instance UID (generate one if not provided in the request)

`OnNSetAsync`:
1. Load existing instance via persistence.GetAsync()
2. If not found, return NoSuchObjectInstance
3. Validate state machine transition:
   - If current status is Completed or Discontinued, return InvalidAttributeValue (terminal states)
   - If modification sets status to something other than Completed or Discontinued, return InvalidAttributeValue
4. Update via persistence.UpdateAsync()
5. Return Success

**StorageCommitmentScpHandler.cs:**
Implements `INActionHandler` (for receiving N-ACTION Storage Commitment Request) and optionally `INEventReportHandler`.

Constructor takes `IStorageVerifier`.

`OnNActionAsync`:
1. Verify SOP Class UID is StorageCommitmentPushModel and Action Type ID is 1
2. Parse StorageCommitmentRequest from action information dataset
3. Call verifier.VerifyAsync() to check which instances are committed
4. Build StorageCommitmentResult
5. For same-association mode: the result should be delivered via N-EVENT-REPORT. For now, store the result and provide a method `GetPendingResults()` that the server can poll. The N-EVENT-REPORT sending mechanism depends on server-side push capability.
6. Return Success status for the N-ACTION (acknowledgment that the request was received)

NOTE: Full N-EVENT-REPORT push (SCP-initiated message to SCU) requires bidirectional message support in DicomServer which is complex. For this plan, implement the verification pipeline and result storage. The result can be delivered on same-association if the SCU waits, or via a separate mechanism. Document the limitation.
