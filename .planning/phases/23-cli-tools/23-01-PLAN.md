**ExitCodes.cs**: Static class with `public const int` fields: `Success = 0`, `UsageError = 1`, `RuntimeError = 2`, `ValidationError = 3`.

**FileEnumerator.cs**: Static class with method `IEnumerable<string> EnumerateFiles(FileSystemInfo[] inputs, bool recursive = true)` that:
- For each input: if file, yield if `.dcm` extension (case-insensitive) or any extension with `--all-files` context
- For each input: if directory, use `Directory.EnumerateFiles(path, "*.dcm", recursive ? SearchOption.AllDirectories : SearchOption.TopDirectoryOnly)`
- Handles non-existent paths by throwing `FileNotFoundException` with descriptive message
- Uses lazy enumeration (yield return), NOT eager collection

**ConnectionStringParser.cs**: Static class with `TryParse(string connectionString, out string? host, out int port, out string? calledAe)`:
- Parses `pacs://AET@host:port` format
- Returns false on invalid format
- Default port 104 if not specified

**ProgressReporter.cs**: Class wrapping Spectre.Console progress:
- Constructor takes `TextWriter stderr` (for progress output to stderr, not stdout)
- `bool IsInteractive` property using `AnsiConsole.Profile.Capabilities.Interactive` check
- `async Task RunWithProgress(string description, int totalItems, Func<Action<int>, CancellationToken, Task> work, CancellationToken ct)` method:
  - If interactive: Spectre.Console Progress bar to stderr with TaskDescription, ProgressBar, Percentage, RemainingTime columns
  - If not interactive: line-per-item logging to stderr
- Progress output ALWAYS goes to stderr (never stdout) to avoid corrupting piped structured output

**IOutputFormatter.cs**: Interface with methods:
- `void WriteFileHeader(string filePath, TextWriter output)` - header before each file's dump
- `void WriteElement(IDicomElement element, DicomDictionary dictionary, DicomDataset dataset, int depth, TextWriter output)` - single element
- `void WriteSequenceStart(DicomTag tag, string keyword, int depth, TextWriter output)`
- `void WriteSequenceItemStart(int itemIndex, int depth, TextWriter output)`
- `void WriteSequenceItemEnd(int depth, TextWriter output)`
- `void WriteSequenceEnd(int depth, TextWriter output)`
- `void WriteFileFooter(TextWriter output)` - footer after each file
- `void WriteBatchHeader(TextWriter output)` / `void WriteBatchFooter(TextWriter output)` - for multi-file runs
- `string FormatName { get; }` - "text", "json", "xml"

**TextFormatter.cs**: Implements IOutputFormatter with dcmdump-style output:
- Format: `(GGGG,EEEE) VR [value] # keyword`
- String values in square brackets
- Known UIDs shown as `=Name` (look up via `DicomUID.GetName`)
- Sequences indented with `>` prefix per depth level
- Pixel data shown as `(pixel data, length=N)`
- Private tags show vendor name when known via `VendorDictionary.GetInfo`
- Uses Spectre.Console markup for color when writing to interactive terminal (tag in cyan, VR in yellow, keyword in green), plain text otherwise. Color detection via `AnsiConsole.Profile.Capabilities.Ansi`.

**JsonFormatter.cs**: Implements IOutputFormatter:
- Uses `System.Text.Json.Utf8JsonWriter` with indented formatting
- WriteBatchHeader writes `[`, WriteBatchFooter writes `]`
- WriteFileHeader writes `{`, WriteFileFooter writes `}`
- Each element as `{ "tag": "00100010", "vr": "PN", "keyword": "PatientName", "value": "Smith^John" }`
- Sequences as nested arrays of objects
- Binary/pixel data as `{ "tag": "...", "vr": "OW", "keyword": "PixelData", "length": 524288 }` (no inline data)

**XmlFormatter.cs**: Implements IOutputFormatter:
- Uses `System.Xml.XmlWriter` with indented formatting for proper escaping
- Root element `<DicomFile>`, elements as `<Element tag="00100010" vr="PN" keyword="PatientName">Smith^John</Element>`
- Sequences as `<Sequence tag="..." keyword="..."><Item>...</Item></Sequence>`

**CliConfig.cs**: Record class with properties:
- `string OutputFormat` (default "text")
- `string Verbosity` (default "normal")
- `bool Color` (default true)
- `bool ContinueOnError` (default false)
- `string? DefaultProfile` (PACS profile name)
- `Dictionary<string, PacsProfile> Profiles` (named PACS connections)

**PacsProfile.cs**: Record class with properties:
- `string Host`
- `int Port` (default 104)
- `string CalledAE`
- `string? CallingAE`
- `bool UseTls` (default false)

**ConfigLoader.cs**: Static class with:
- `CliConfig Load(string? configPath = null)`: Load from `~/.sharpdcm/config.toml` using Tomlyn. If file doesn't exist or has parse errors, log warning to stderr and return defaults. Never throw on config errors.
- `CliConfig ApplyEnvironmentVariables(CliConfig config)`: Override with `SHARPDCM_OUTPUT_FORMAT`, `SHARPDCM_VERBOSITY`, `SHARPDCM_COLOR` env vars
- Config loading is lazy - called by commands that need it, not at startup

**Program.cs**: Entry point that:
- Creates `RootCommand("SharpDicom command-line toolkit")` with description
- Adds global options: `--format`/`-f` (text/json/xml), `--verbose`/`-v`, `--quiet`/`-q`, `--debug`, `--no-color`, `--config` (path override), `--continue-on-error`
- Adds 5 stub subcommands: `dump`, `store`, `find`, `lint`, `fix` - each with a brief description and a handler that prints "Not yet implemented" and returns ExitCodes.UsageError
- Returns `rootCommand.Parse(args).InvokeAsync()` as the main entry point
- Uses top-level statements pattern
- Version display via `--version` showing SharpDicom assembly version

CRITICAL anti-patterns to avoid:
- Do NOT use `Console.WriteLine` directly in formatter logic - always use the `TextWriter output` parameter
- Do NOT call `.Result` or `.GetAwaiter().GetResult()` - System.CommandLine supports async actions via `SetAction`
- Progress output MUST go to stderr, NOT stdout
- Config errors MUST NOT prevent `--help` or other commands from running
  </action>
