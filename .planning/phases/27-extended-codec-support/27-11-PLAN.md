```csharp
// Video codec registration - to be implemented in future plan
// if (HasFeature(NativeCodecFeature.Video))
// {
//     CodecRegistry.Register(new NativeVideoCodec(), CodecRegistry.PriorityNative);
// }
```

Replace it with:
```csharp
// Video encoder backend registration
if (HasFeature(NativeCodecFeature.VideoEncoder))
{
    VideoEncoder.RegisterBackend((frames, options, width, height, progress) =>
    {
        using var encoder = new NativeVideoEncoder(options, width, height);
        foreach (var frame in frames)
            encoder.EncodeFrame(frame);
        encoder.Flush();
        return encoder.GetOutput();
    });
}
```

Key design points:
- Use NativeCodecFeature.VideoEncoder (not .Video) -- VideoEncoder is the encoding-specific feature flag that checks for NativeFeatures.VideoEnc and EnableVideo.
- The delegate wraps NativeVideoEncoder's full lifecycle: create -> encode frames -> flush -> get output.
- NativeVideoEncoder is IDisposable; the `using var` ensures cleanup.
- The `progress` parameter is not forwarded to NativeVideoEncoder because the native encoder does not have a progress callback API -- this is by design; progress reporting happens at the VideoEncoder static API level.

Also add the required using directive at the top of the file if not already present:
- `using SharpDicom.Codecs.Video;` (for VideoEncoder, VideoFrame, VideoEncoderOptions, VideoEncodeProgress)
- `using SharpDicom.Codecs.Native;` (for NativeVideoEncoder)

Check existing using directives first -- some may already be present.
