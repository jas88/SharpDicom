  <action>
1. Add SHARPDICOM_HAS_JPEG12 feature flag to sharpdicom_codecs.h:
   `#define SHARPDICOM_HAS_JPEG12 (1 << 9)` (next available bit after SHARPDICOM_HAS_TESSERACT at bit 8).

2. Update sharpdicom_codecs.c `sharpdicom_features()` to include SHARPDICOM_HAS_JPEG12 when compiled with SHARPDICOM_WITH_JPEG12.

3. Create native/src/jpeg12_wrapper.h with:
   - `jpeg12_decode(input, inputLen, output, outputLen, width, height, components)` -- decodes 12-bit JPEG to uint16_t pixel data
   - `jpeg12_encode(input, width, height, components, output, outputLen, quality)` -- encodes uint16_t pixel data to 12-bit JPEG
   - `jpeg12_free(buffer)` -- frees buffer allocated by jpeg12_encode
   - `jpeg12_has_support()` -- returns 1 if 12-bit support compiled in

4. Create native/src/jpeg12_wrapper.c implementing the 12-bit JPEG functions:

   The implementation uses the RAW libjpeg API (NOT TurboJPEG), because building libjpeg-turbo with WITH_12BIT disables TurboJPEG.

   For decode:
   - Call jpeg12_jpeg_CreateDecompress (the prefixed version of jpeg_CreateDecompress)
   - Set up memory source via jpeg12_jpeg_mem_src
   - Read header via jpeg12_jpeg_read_header
   - Start decompression via jpeg12_jpeg_start_decompress
   - Read scanlines via jpeg12_jpeg_read_scanlines (each sample is JSAMPLE which is 12-bit in the 12-bit build)
   - Copy 12-bit JSAMPLE values to uint16_t output buffer
   - Cleanup via jpeg12_jpeg_destroy_decompress

   For encode:
   - Call jpeg12_jpeg_CreateCompress
   - Set up memory destination via jpeg12_jpeg_mem_dest
   - Set image parameters (width, height, components, precision=12)
   - Start compression via jpeg12_jpeg_start_compress
   - Write scanlines via jpeg12_jpeg_write_scanlines
   - Finish via jpeg12_jpeg_finish_compress
   - Copy output buffer, cleanup via jpeg12_jpeg_destroy_compress

   Error handling: use setjmp/longjmp error handler pattern standard for libjpeg. Store error message in thread-local storage via sharpdicom_set_error().

   CRITICAL: All libjpeg function calls use the `jpeg12_` prefix because the 12-bit build has its symbols prefixed via -D flags at compile time. The actual symbol names in the object files will be `jpeg12_jpeg_CreateCompress`, etc.

   When SHARPDICOM_WITH_JPEG12 is not defined, all functions should return SHARPDICOM_ERR_UNSUPPORTED (stub pattern matching existing wrappers).
  </action>
