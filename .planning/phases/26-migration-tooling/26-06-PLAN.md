    4. **DiagnosticIds.cs**:
       - `SD0001` = "fo-dicom using directive detected" (using FellowOakDicom or using Dicom)
       - `SD0002` = "fo-dicom type instantiation detected" (new DicomFile, new DicomDataset, etc.)
       - `SD0003` = "fo-dicom static method call detected" (DicomFile.Open, etc.)
       - `SD0010` = "Compat layer using directive detected" (step 2)
       - `SD0011` = "Compat layer type usage detected" (step 2)
       - Each as a `public const string` field

    5. **FoDicomUsageAnalyzer.cs** (DiagnosticAnalyzer):
       - `SupportedDiagnostics`: SD0001, SD0002, SD0003
       - `Initialize`:
         a. `context.ConfigureGeneratedCodeAnalysis(GeneratedCodeAnalysisFlags.None)`
         b. `context.EnableConcurrentExecution()`
         c. Register `SyntaxKind.UsingDirective` handler -> check if namespace starts with `FellowOakDicom` or equals `Dicom` -> report SD0001
         d. Register `SymbolKind.NamedType` handler (semantic analysis) -> check if type's containing namespace starts with `FellowOakDicom` or equals `Dicom` -> report SD0002
         e. Register `SyntaxKind.InvocationExpression` handler -> check if method belongs to fo-dicom types -> report SD0003
       - Use semantic analysis (not just syntax) to avoid false positives on user types named "Dicom" (per RESEARCH.md anti-pattern)

    6. **CompatUsageAnalyzer.cs** (DiagnosticAnalyzer):
       - `SupportedDiagnostics`: SD0010, SD0011
       - Detects `using SharpDicom.FoDicom5.Compat.FellowOakDicom` or `using SharpDicom.FoDicom4.Compat.Dicom`
       - Reports SD0010 on using directives, SD0011 on type usage
       - Default severity: Info (these are informational for the second migration step)

    7. Build: `dotnet build src/SharpDicom.Analyzers/`

    1. **FoDicomToCompatFix.cs** (CodeFixProvider):
       - `FixableDiagnosticIds`: SD0001
       - `GetFixAllProvider`: return `WellKnownFixAllProviders.BatchFixer` (per RESEARCH.md)
       - `RegisterCodeFixesAsync`:
         a. Find the `UsingDirectiveSyntax` at the diagnostic location
         b. Register code fix: "Replace with SharpDicom.FoDicom5.Compat"
         c. The fix rewrites the using directive:
            - `using FellowOakDicom;` -> `using SharpDicom.FoDicom5.Compat.FellowOakDicom;`
            - `using FellowOakDicom.Network;` -> `using SharpDicom.FoDicom5.Compat.FellowOakDicom.Network;`
            - `using FellowOakDicom.Network.Client;` -> `using SharpDicom.FoDicom5.Compat.FellowOakDicom.Network.Client;`
            - `using Dicom;` -> `using SharpDicom.FoDicom4.Compat.Dicom;`
            - `using Dicom.Network;` -> `using SharpDicom.FoDicom4.Compat.Dicom.Network;`
         d. Pattern: prepend `SharpDicom.FoDicom5.Compat.` for FellowOakDicom namespaces, `SharpDicom.FoDicom4.Compat.` for Dicom namespaces

    2. **CompatToNativeFix.cs** (CodeFixProvider):
       - `FixableDiagnosticIds`: SD0010
       - `RegisterCodeFixesAsync`:
         a. Find the using directive
         b. Register code fix: "Replace with native SharpDicom"
         c. Rewrite using directives:
            - `using SharpDicom.FoDicom5.Compat.FellowOakDicom;` -> `using SharpDicom.Data;` (+ `using SharpDicom;` if DicomFile used)
            - `using SharpDicom.FoDicom5.Compat.FellowOakDicom.Network;` -> `using SharpDicom.Network;`
         d. Note: This is a simplified namespace rewrite. Full API-level migration (e.g., GetSingleValue -> GetString) would need per-method fixes, which is a future enhancement.

    3. Build and verify
