<objective>
Create the SharpDicom.FoDicom5.Compat project with all core fo-dicom 5.x types needed for file I/O compatibility. This is the foundation that dcm2csv validation and all other compat work depends on.

Purpose: Provide a drop-in replacement for fo-dicom's core `FellowOakDicom` namespace types so that projects can swap their NuGet reference and compile without code changes.
Output: SharpDicom.FoDicom5.Compat project with DicomFile, DicomDataset, DicomTag, DicomVR, DicomUID, DicomItem hierarchy, DicomSequence, plus unit tests.

Note on scope: This plan touches ~20 files, but they are all small, tightly-coupled wrapper types following a single composition pattern. Splitting would create artificial boundaries -- e.g., DicomItem.Wrap needs DicomStringElement, DicomSequence, DicomAttributeTag to all exist. The types form one cohesive unit.
</objective>

    - Properties: `UID` (string), `Name` (string), `Type` (enum)
    - Static well-known UIDs as needed (Verification SOP Class, Study Root Find, etc.)

    **DicomItem.cs** - Abstract base class for all compat elements:
    - Property: `Tag` (compat DicomTag)
    - Internal property: `Inner` (SharpDicom `IDicomElement`)
    - Internal static factory method: `Wrap(IDicomElement element)` returns correct subclass using pattern matching:
      - `DicomSequence` -> compat `DicomSequence`
      - `DicomNumericElement` with VR==AT -> compat `DicomAttributeTag`
      - `DicomStringElement` -> compat `DicomStringElement`
      - Everything else -> compat `DicomOtherElement`
    - Abstract `ValueRepresentation` property returning compat `DicomVR`
    - Override `ToString()` to show tag and value summary

    **DicomElement.cs** - Abstract class extending DicomItem for value elements (not sequences):
    - Property: `Count` (int) -- number of VM values
    - Generic method: `Get<T>(int index = 0)` with typed dispatch:
      - `typeof(T) == typeof(string)`: extract string at index
      - `typeof(T) == typeof(int)`: parse int at index
      - `typeof(T) == typeof(double)`: parse double at index
      - Throw `DicomDataException` for unsupported types

    **DicomStringElement.cs** - Concrete class for string-VR elements:
    - Wraps `SharpDicom.Data.DicomStringElement`
    - `Count` returns number of backslash-separated values (via `GetStrings()?.Length ?? 0`)
    - `Get<string>(index)` returns specific VM value

    **DicomAttributeTag.cs** - Concrete class for AT-VR elements:
    - Wraps `SharpDicom.Data.DicomNumericElement` where VR==AT
    - Property: `Values` returning `DicomTag[]` -- parse raw bytes as pairs of (group, element)
    - `Count` returns number of tag values

    **DicomOtherElement.cs** - Fallback wrapper for binary/other element types:
    - Wraps any `IDicomElement` not matching above specializations
    - `ToString()` shows "[binary data]" or similar

    **DicomSequence.cs** - Wrapper for sequences:
    - Property: `Items` returning `IReadOnlyList<DicomDataset>` (compat datasets wrapping inner items)

    **Exceptions/DicomDataException.cs** - Exception type matching fo-dicom's:
    - Extends `Exception`
    - Same constructor signatures as fo-dicom

    **Compatibility.cs** - Extension methods:
    - `Unwrap()` extension methods on compat DicomFile, DicomDataset, DicomTag, DicomSequence
