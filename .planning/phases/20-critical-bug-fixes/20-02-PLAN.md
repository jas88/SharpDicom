Replace that section with SequenceParser integration:

1. Add a `using SharpDicom.IO;` statement at the top of the file if not present (for SequenceParser).

2. Create a SequenceParser instance inside ParseDataset, configured with the same explicitVR and littleEndian settings:
```csharp
var sequenceParser = new SequenceParser(
```

3. When encountering an undefined-length element:
   - If it's PixelData: keep existing behavior (store all remaining bytes)
   - If VR is SQ (sequence): use SequenceParser.ParseSequence to parse it
   - For undefined-length non-SQ non-PixelData: throw (this is the existing behavior in SequenceParser)

4. Replace the skip block (lines 599-602) with:
```csharp
if (valueLength == 0xFFFFFFFF)
{
    // Undefined length element
    if (tag == DicomTag.PixelData && reader.Remaining > 0)
    {
        // Encapsulated pixel data - store all remaining bytes
        var remainingData = reader.ReadBytes(reader.Remaining);
        var pixelElement = new DicomBinaryElement(tag, vr, remainingData.ToArray());
        dataset.Add(pixelElement);
    }
    else if (vr == DicomVR.SQ)
    {
        // Sequence with undefined length - parse using SequenceParser
        // The remaining buffer contains the sequence content plus trailing elements
        var remainingBuffer = span.Slice(reader.Position);
        var sequence = sequenceParser.ParseSequence(remainingBuffer, tag, valueLength, dataset);
        dataset.Add(sequence);

        // Advance reader position past the sequence content and delimiter
        // We need to find where the sequence ends (SequenceDelimitationItem)
        var bytesConsumed = FindSequenceEndPosition(remainingBuffer, transferSyntax.IsExplicitVR, transferSyntax.IsLittleEndian);
        reader.Skip(bytesConsumed);
    }
    else
    {
        // Undefined length for non-SQ/non-PixelData is not supported
        throw new DicomDataException($"Undefined length for non-sequence element {tag} not supported");
    }
    continue;
}
```

5. Add a helper method to find sequence end position (or reuse/adapt logic from SequenceParser.FindSequenceContentLength):
```csharp
private static int FindSequenceEndPosition(ReadOnlySpan<byte> buffer, bool explicitVR, bool littleEndian)
{
    // Scan for SequenceDelimitationItem (FFFE,E0DD) accounting for nesting
    // Returns bytes consumed including the delimiter (8 bytes: tag + zero length)
    // This is similar to SequenceParser.FindSequenceContentLength but returns content + delimiter size
    int contentLength = FindSequenceContentLengthStatic(buffer, explicitVR, littleEndian);
    return contentLength + 8; // Add 8 bytes for SequenceDelimitationItem
}
```

6. Also handle defined-length sequences in the main parsing loop. After line 605 (`if (!reader.TryReadValue(valueLength, out var value))`), add sequence handling for defined-length SQ:
```csharp
if (vr == DicomVR.SQ)
{
    // Sequence with defined length
    var seqBuffer = span.Slice(reader.Position - (int)valueLength, (int)valueLength);
    var sequence = sequenceParser.ParseSequence(seqBuffer, tag, valueLength, dataset);
    dataset.Add(sequence);
    continue;
}
```

Note: The DicomStreamReader is a ref struct with a Skip method. If Skip doesn't exist, use equivalent position manipulation. Check the actual API and adapt accordingly.

Key constraint: Do NOT replace ParseDataset with DicomFileReader. Keep the streaming approach - the data is already in memory as `byte[] data`, we just need to parse sequences properly from that buffer.
