  <name>Task 1: Fix DicomStreamReader.FindSequenceDelimiter</name>
  <files>src/SharpDicom/IO/DicomStreamReader.cs</files>
  <action>
Fix the depth tracking bug in FindSequenceDelimiter method (around line 296-364).

Current buggy pattern (lines 339-344):
```csharp
else if (tag == DicomTag.SequenceDelimitationItem)
{
    // Nested sequence delimiter
    depth--;  // BUG: decrements even when depth == 0
    searchPos += 8;
}
```

Replace with correct pattern (from SequenceParser.cs lines 451-460):
```csharp
else if (tag == DicomTag.SequenceDelimitationItem)
{
    if (depth == 0)
    {
        // Found the end of our sequence - this is the FIRST check
        return searchPos;
    }
    // Nested sequence ended
    depth--;
    searchPos += 8;
}
```

Key insight: The depth == 0 check for SequenceDelimitationItem on line 313 never triggers because the tag match on line 313 only fires when BOTH conditions are true. But the else-if on line 339 catches all OTHER SequenceDelimitationItem tags (nested ones) and decrements unconditionally.

The fix restructures the logic so:
1. Line 313's condition is removed (it's redundant)
2. The else-if for SequenceDelimitationItem checks depth == 0 FIRST and returns
3. Only then does it decrement depth for nested sequences
