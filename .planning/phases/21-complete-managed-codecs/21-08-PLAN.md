  <action>
The WriteNumPasses and ReadNumPasses have a format mismatch per 21-06-SUMMARY.md.

**ITU-T T.800 Table B.4 specifies:**
| Passes | Coding |
|--------|--------|
| 1 | 0 |
| 2 | 10 |
| 3-5 | 11xx (00, 01, 10 for 3, 4, 5) |
| 6-36 | 1111 + 5 bits (0-30) |
| 37-164 | 1111 1111 + 7 bits (0-127) |

**Current encoder (WriteNumPasses):**
- 1: 0
- 2: 10
- 3-5: 11xx (correct)
- 6-36: 1111 + 5 bits (says "passes - 6" giving 0-30) - CORRECT
- 37+: 1111 1111 + 7 bits (says "passes - 37") - CORRECT

**Current decoder (ReadNumPasses):**
- 1: 0 (correct)
- 2: 10 (correct)
- 3-5: 11xx + next2 < 3 -> 3 + next2 (correct for 00, 01, 10)
- BUT: next2 == 3 (11) means prefix is 1111, decoder then reads more...

The decoder logic for 6-36 range is:
```csharp
// 1111xxxxx or 11111111xxxxxxx
if (ReadBit() == 0)
{
    // 11110xxxx
    return 6 + ReadBits(4);  // BUG: This reads 4 bits, should read 5
}
```

The encoder writes:
```csharp
else if (passes <= 36)
{
    // 1111 + 5-bit suffix
    WriteBit(1); WriteBit(1); WriteBit(1); WriteBit(1);
    int suffix = passes - 6;
    // Writes 5 bits
}
```

**The fix:**
1. In PacketDecoder.ReadNumPasses(), after detecting 1111 prefix, read 5 bits (not 4) for range 6-36.

Actually, looking more carefully at the decoder:
- After 11xx where x = 3 (i.e., 1111), it reads another bit
- If that bit is 0 -> "11110" -> reads 4 bits -> 6 + ReadBits(4) = 6-21
- If that bit is 1 -> reads another bit...

But the encoder writes:
- For 6-36: "1111" + 5 bits

There's a structural mismatch. The decoder expects a tree structure (1111, 111110, 1111110, etc.) while the encoder uses fixed-length suffixes.

**Correct fix per ITU-T T.800:**
Both should use:
- 1: 0
- 2: 10
- 3-5: 11 + 2 bits (00=3, 01=4, 10=5)
- 6-36: 1111 + 5 bits (value = 6 + bits)
- 37-164: 11111111 + 7 bits (value = 37 + bits)

Fix the decoder to match this:
```csharp
private int ReadNumPasses()
{
    if (ReadBit() == 0) return 1;
    if (ReadBit() == 0) return 2;

    int next2 = ReadBits(2);
    if (next2 != 3)
    {
        return 3 + next2; // 3, 4, or 5
    }

    // next2 == 3 means we've read "1111"
    // Check for extended format (11111111)
    int next4 = ReadBits(4);
    if (next4 != 15)
    {
        // 1111 + 5 bits: we have 4 bits, read 1 more
        int extraBit = ReadBit();
        int suffix = (next4 << 1) | extraBit;
        return 6 + suffix; // 6-36
    }

    // 11111111 + 7 bits
    return 37 + ReadBits(7);
}
```

Also update encoder to be clearer and match exactly.
