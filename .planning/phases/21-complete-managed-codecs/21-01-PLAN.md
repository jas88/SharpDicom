First, analyze existing JpegLsEncoder.cs and JpegLsDecoder.cs (~1000 lines combined) to understand
what functionality already exists vs needs to be created. Then create three NEW files with complete
implementations, extracting any reusable code from existing files:

1. **JpegLsPredictor.cs** - All 8 predictor modes from ITU-T T.87 Section 4.2:
   - Mode 0: Reserved (use mode 1)
   - Mode 1: a (horizontal)
   - Mode 2: b (vertical)
   - Mode 3: c (diagonal)
   - Mode 4: a + b - c
   - Mode 5: a + (b - c) / 2
   - Mode 6: b + (a - c) / 2
   - Mode 7: (a + b) / 2
   - Include MedianEdgeDetection (MED) for automatic mode selection based on gradients

2. **JlsContext.cs** - Context state machine (ITU-T T.87 Section 4.3):
   - struct JlsContext with fields: A (accumulated absolute error), B (accumulated signed error), C (bias correction), N (sample count)
   - Initialize() method per range value
   - ComputeK() method for Golomb-Rice parameter
   - Update() method with bias correction and overflow prevention
   - Use readonly struct for performance

3. **GolombRiceCoder.cs** - Entropy coding (ITU-T T.87 Section 4.5):
   - ref struct GolombRiceEncoder with WriteBit, WriteGolombRice, Flush methods
   - ref struct GolombRiceDecoder with ReadBit, ReadGolombRice methods
   - Proper JPEG bit-stuffing (insert 0x00 after 0xFF bytes)
   - Error mapping: even/odd mapping for signed errors
   - Limited parameter k (k < 32 to prevent overflow)

Key implementation details from research:
- Context index formula: `(q1 * 9 + q2) * 9 + q3 + (9 * 9 * 4)` gives 0-364 range
- Gradient quantization thresholds: T1=3+NEAR, T2=7+NEAR, T3=21+NEAR
- Sign normalization: if (q1 < 0) or (q1==0 and q2 < 0) or (q1==0 and q2==0 and q3 < 0), negate all and flip sign flag
  </action>
