  <action>
  **DicomDateRange** (`src/SharpDicom/Network/Dimse/Services/DicomDateRange.cs`):
  Create a readonly record struct `DicomDateRange` with `DateTime? From` and `DateTime? To` properties.
  - Static method `Parse(string value)` handles:
    - Single date: "YYYYMMDD" -> (date, date)
    - Range: "YYYYMMDD-YYYYMMDD" -> (from, to)
    - Open start: "-YYYYMMDD" -> (null, to)
    - Open end: "YYYYMMDD-" -> (from, null)
    - Empty/null -> (null, null)
  - Use `DateTime.ParseExact` with format "yyyyMMdd" and `CultureInfo.InvariantCulture`
  - Add `bool Contains(DateTime date)` method for in-memory matching
  - Add `bool IsUniversal` property (true when both From and To are null)

  **DicomQueryMatcher** (`src/SharpDicom/Network/Dimse/Services/DicomQueryMatcher.cs`):
  Create a static class with:
  - `DicomWildcardToSqlLike(string dicomPattern)` — translates DICOM `*` to `%`, `?` to `_`, escapes literal `%`, `_`, `\` in the pattern. Uses `StringBuilder`. Returns (sqlLikePattern, hasWildcard) tuple.
  - `HasDicomWildcard(string value)` — returns true if value contains `*` or `?`
  - `FilterReturnKeys(DicomDataset match, DicomDataset requestIdentifier)` — creates new DicomDataset containing only tags present in requestIdentifier (the query), plus always includes QueryRetrieveLevel. Per DICOM PS3.4 C.2.2.
  - `MatchesWildcard(string value, string pattern, bool caseInsensitive)` — in-memory wildcard matching using simple recursive or iterative algorithm (for non-SQL matching). UIDs never use wildcards.

  **DicomServerOptions** (`src/SharpDicom/Network/DicomServerOptions.cs`):
  Add these callback properties (all `init`):
  - `Func<DicomDataset, CancellationToken, IAsyncEnumerable<DicomDataset>>? OnCFind { get; init; }` — receives the query identifier dataset, returns streaming matches. The dataset contains QueryRetrieveLevel and matching/return keys.
  - `Func<DicomDataset, CancellationToken, ValueTask<DicomFile?>>? OnCMoveRetrieve { get; init; }` — given a matched dataset (from OnCFind), retrieves the actual DicomFile for forwarding.
  - `Func<DicomDataset, CancellationToken, ValueTask<DicomFile?>>? OnCGetRetrieve { get; init; }` — same as OnCMoveRetrieve but for C-GET.
  - `Func<string, (string Host, int Port)?>? OnResolveMoveDestination { get; init; }` — resolves AE title to host:port for C-MOVE forwarding.
  - Add `bool HasCFindHandler => OnCFind != null;` convenience property
  - Add `bool HasCMoveHandler => OnCFind != null && OnCMoveRetrieve != null && OnResolveMoveDestination != null;` — needs all three
  - Add `bool HasCGetHandler => OnCFind != null && OnCGetRetrieve != null;` — needs find + retrieve

  **DicomServer.cs** — Extend ExtractDimseRequests:
  - Add to the `CommandFields` private class: `CFindRequest = 0x0020`, `CMoveRequest = 0x0021`, `CGetRequest = 0x0010`, `CCancelRequest = 0x0FFF`
  - In `ExtractDimseRequests`, add detection for C-FIND-RQ (0x0020), C-MOVE-RQ (0x0021), C-GET-RQ (0x0010), C-CANCEL-RQ (0x0FFF)
  - Create a `QRCommandInfo` struct (similar to `CStoreCommandInfo`) to hold: PresentationContextId, MessageID, SOPClassUID, HasDataset, CommandField (to distinguish find/move/get), MoveDestination (for C-MOVE)
  - Parse MoveDestination from command tag (0000,0600) for C-MOVE requests
  - Add `List<QRCommandInfo> QRRequests` to the return tuple of `ExtractDimseRequests`
  - In `HandlePDataAsync`, process QR requests after echo and store
  - Add `ParseMoveDestination(ReadOnlySpan<byte> commandData)` static method

  Add `HandleCFindAsync` method to DicomServer:

  1. Read the identifier dataset from subsequent P-DATA PDUs (reuse existing `ReadDatasetAsync` + `ParseDataset` pattern from HandleCStoreAsync)
  2. If `_options.OnCFind` is null: return failure status 0xA900 (Unable to Process) — still must read and discard the dataset first (CRITICAL: per Pitfall 7 in RESEARCH.md)
  3. If callback registered:
     - Invoke `_options.OnCFind(identifierDataset, ct)` to get `IAsyncEnumerable<DicomDataset>`
     - For each match: filter return keys via `DicomQueryMatcher.FilterReturnKeys(match, identifierDataset)`, then send Pending C-FIND-RSP with identifier using `SendDimseResponseWithDatasetAsync`
     - After all matches: send final C-FIND-RSP with Success status and no dataset
     - Wrap in try/catch: on exception, send failure status 0xCxxx (Unable to Process)
  4. Handle C-CANCEL: Use a CancellationTokenSource that is cancelled when a C-CANCEL-RQ with matching MessageIDBeingRespondedTo is received. For simplicity in this plan, the C-CANCEL handler can set a flag or cancel a CTS that HandleCFindAsync checks between iterations.

  Add `SendDimseResponseWithDatasetAsync` helper method:
  - Takes: Stream, byte presentationContextId, DicomCommand responseCommand, DicomDataset? identifierDataset, CancellationToken
  - Serializes the command dataset using the existing Implicit VR LE pattern (reuse BuildCommandBytes helper or use DicomCommand.Dataset serialization)
  - If identifierDataset is not null, serialize it using the transfer syntax from the accepted presentation context (use DicomStreamWriter or DicomFileWriter.WriteDataset)
  - Wrap both command and dataset in P-DATA PDVs and send

  Add `BuildCommandDatasetBytes(DicomCommand command)` helper:
  - Serializes a DicomCommand's underlying dataset to Implicit VR Little Endian bytes
  - Iterate over command.Dataset elements, write each as tag(4) + length(4) + value in LE
  - This replaces the manual BuildCEchoResponseCommand/BuildCStoreResponseCommand pattern with a generic version

  Add `SerializeDatasetBytes(DicomDataset dataset, byte contextId, DicomAssociation association)` helper:
  - Gets the accepted transfer syntax for the context ID
  - Uses DicomStreamWriter to serialize dataset elements to a byte array
  - Returns the serialized bytes
